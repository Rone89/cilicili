# Build 50：快速暂停／播放与取消搜索回归

## 自动计划

在原有七种情景上新增三种，全部各三次，共 **30 次**，报告 schema 3；保留 schema 1/2 读取兼容。视频门槛、准备跳转、465 秒正常暂停总时长、取消／中断所有权和帧保护均保留。

| 新情景 | 命令 | 完成要求 |
| --- | --- | --- |
| immediateResume | pause → play，无额外 hold | 停用等待期间发出过 play；最后 play ID 的推进帧；最终播放意图和状态 |
| rapidTogglePlaying | pause → play → pause → play，间隔 20ms | 同上；较早 play 的帧不能代替最后 play |
| rapidTogglePaused | pause → play → pause → play → pause，间隔 20ms | 停用等待期间发出过 play；停用等待结束；再采样保持暂停一秒 |

新情景的 commands 记录 action、相对试验开始时间、同步命令跨度，以及命令前的 audioDeactivationPending（可为未知）。这项 pending 包括已提交但尚未进入系统调用的工作，不证明系统调用已并发执行。普通立即情景覆盖不让出主线程时的已提交操作；反复情景的 20ms 间隔让工作队列有机会开始，实际时点以报告为准，不假定精确调度。

没有取得 pending 重叠证据时，即使最终能播放也记录 missingEvidence，不声称竞争被验证；只有较早帧、超时或最终状态不符也不能 observed。保持暂停情景发现意外播放会失败并保留报告。语义命令仍不等于真实手势、可见黑帧或声音输出，切后台、导航、耳机和系统音频中断仍需额外真机验收；正常计划遇中断仍按原策略终止，不自动重启。

## UI 修复与诊断

### 搜索取消

失败截图与触摸日志显示：principal 标题中的搜索行可以绘制到 UIKit 标题点击区域外，Cancel 中心命中导航栏容器，按钮 action 没有执行。旧外部点击识别器还只排除输入胶囊，可能先结束编辑并移除取消按钮。此前将此项误称为键盘收起失败，实际第 43 行断言为未恢复热搜页。

保留 principal 搜索行，改用 idealWidth/maxWidth 接受 UIKit 实际提出的较小宽度，避免固定 frame 强行绘制到点击边界之外；同一个行外点击识别器覆盖完整行，排除 Clear 和 Cancel。取消动作结束第一响应者并清空查询与编辑状态。最终源码移除临时触摸日志；没有在测试里补按“清空”或放宽发现页断言。最终搜索全组 13/13 通过，覆盖取消、反复提交／取消、滚动、筛选、详情返回、我的页和宽度回收。

### 评论原生键盘

复现层级显示原生中文九宫格已恢复，有 A B C 分组键和 identifier=space 的空格键；旧测试要求独立 a/A 键，错误地绑定了英文 QWERTY 布局。改为等待并验证可点击的原生 space 键，再实际输入追加文字并断言完整内容；不改变产品输入法，不强制英文，也不删除键盘恢复／可输入断言。
