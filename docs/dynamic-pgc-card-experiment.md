# 动态番剧卡片与播放增强实验

入口：我的 → 开发者与诊断 → 实验开关 → 动态番剧卡片与播放增强实验。默认关闭，设置持久化；关闭后恢复原有动态图文回退展示，不清理账号或观看记录。

## 行为与范围

- 仅识别 `DYNAMIC_TYPE_PGC` / `DYNAMIC_TYPE_PGC_UNION` 的 `major.pgc`；同样支持 `orig` 内的番剧动态。普通文字提及追番不会转换。
- 独立原生番剧卡片：16:9 封面、标题，以及接口实际返回的 badge、duration_text、stat.play、stat.danmaku；转发使用紧凑卡片。正文、作者、原动态评论 OID/type 和动态互动不变。
- 移除回退图文中的重复番剧封面与标题，保留正文及其他图片。封面复用 CDN 缩略图、RemoteImageCache 和现有视频封面阴影设置。
- 优先 `epid`，仅在缺失时解析 Bilibili 正规 `/bangumi/play/ep...` 链接；`season_id` / `ss...` 为无分集信息时的降级。不会将 `id`、`aid` 或真假布尔值当作分集 ID。
- 复用 `fetchPgcSeasonInfo(seasonID:epID:)`、`/pgc/view/web/season` 和现有 PGC 播放链路，不新增网络端点或卡片级分集预请求。
- 指定分集必须在返回的可播放分集中准确匹配，优先于云端续播记录；失效或缺少可播放 CID 时提示失败，绝不自动播放另一集。原有仅 season 的搜索/追番入口仍按原续播规则选择。
- 已知分集直接进入视频详情页，使用封面/标题作为种子，分集 CID 在现有详情加载流程内解析，不再先展示独立整页加载界面；不伪造可播放信息，不改变播放引擎。
- 分集加载失败在播放器区域提示，支持重试、网页查看和原底栏返回。重试使用随视图取消的 `.task`，沿用详情加载的取消/退出/身份校验，避免退出后的状态提交。季级入口保留原有加载与续播行为。
- 番剧继续显示于“全部”，不加入“视频”筛选；最常访问区和多账号配置不变。

## 指定分集启动优化（2026-10-12）

- 冷签名缓存时，原流程为分集解析 → 获取 WBI 密钥 → 播放地址。现在在详情 `load()` 开始时用现有任务管理启动签名预热，与分集解析并行；详情信息不等待预热，预热失败仍由正式播放请求处理。只针对打开的番剧，不对动态列表所有卡片预请求。
- 关键分集查询使用 URLSession 高优先级和 responsiveData。分集列表在真实 CID 已解析后加载，复用原有按请求认证头隔离的 response cache；其 task 身份加入 CID，使未知 CID 到已知 CID 的转换会触发加载。普通调用默认优先级保持不变。
- 精确分集选择直接扫描 episodes/section，只有 ID 匹配时才检查可播放，不再先为整季分集创建 VideoItem。继续支持附加分集和不可播放同 ID 项的降级查找，不切换到另一集。
- 保留播放质量、编码回退、HLS Bridge、缓冲、播放引擎、账号认证和界面结构；签名缓存/请求合并沿用现有服务。

## 播放成功但简介/分集停留骨架屏（2026-10-12）

- 状态同步缺口：简介页只有同一个 viewModel 引用作为输入，父层 revision 更新后，SwiftUI 可跳过其 body；从 ep 种子解析出的 CID 未传入分集组件，等待 CID 的任务不重启，季信息、交互按钮和分集仍为加载占位。
- 将真实 `VideoItem` 作为简介页的显式值输入，通过现有结构更新门控传递；保留旋转期间的更新合并，避免观察整个 viewModel 的高频播放发布。分集组件显式复用详情页的 API client。
- 新增真实 SwiftUI hosting 回归测试：保持父级与 viewModel 身份，种子解析后检查简介区从骨架屏扩展为季信息/操作/分集，且分集复用前台查询缓存，不增加网络请求。
