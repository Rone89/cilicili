# 收藏夹与稍后再看管理增强实验

入口：我的 → 开发者与诊断 → 实验功能。默认关闭，不删除服务器数据或本地设置；最低 iOS 26.1 不变。

## 实现与接口

- 收藏夹使用现有列表、卡片和分页，新增系统 List 多选、滑动操作、上下文菜单、底部 toolbar 和目标收藏夹选择 sheet。
- `/x/v3/fav/resource/batch-deal`：resources 为 aid:2 列表；复制只传 add_media_ids；移动先复制，确认成功后再传 del_media_ids；移除只取消来源收藏夹关系。
- 每批最多 20 项，顺序请求。失败停止后续批次；移动第二步失败明确报告已复制但未移除，不宣称全部成功。操作后重新读取服务器状态，包括超时情况。
- 收藏夹创建/编辑/删除/排序使用 folder/add、folder/edit、folder/del、folder/sort；编辑前读取 folder/info，保留 cover，并支持 title、intro、privacy。默认收藏夹不可编辑、删除或移动位置；管理操作要求 owner mid 与当前收藏账号一致。
- 稍后再看使用现有读取接口；写入使用 toview/add、toview/v2/dels（resources 为 aid 列表）、toview/clear。清空须系统确认，popover 可点击外部取消。继续播放复用既有视频导航及恢复进度。
- 视频详情底部「…」系统菜单提供稍后再看操作，读取真实成员状态；收藏与稍后再看各自维护变更版本，相关页面重新同步。
- 收藏使用 interaction 请求账号，稍后再看使用 historyRead。批量操作绑定实际显示数据的账号上下文，提交前后校验身份/凭据；账号切换清空对应缓存和选择，晚到旧请求不回填新账号。
- 收藏夹刷新重新获取此前已加载页，保留稳定行 ID；全选仅包含已加载且具有有效 aid 的视频。

## 参考范围

研究 PiliPlus commit 3997a46 的 lib/http/fav.dart、lib/http/user.dart，以及收藏详情、创建、排序、稍后再看 controller/model。复用其经过实际使用的接口参数约定，界面使用原生 SwiftUI；移动采用可报告两阶段失败的 batch-deal，而非复制 Flutter UI。
