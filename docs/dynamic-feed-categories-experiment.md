# 动态分类与 UP 筛选实验

入口：我的 → 开发者与诊断 → 实验开关 →「动态分类与 UP 筛选」。默认关闭。

## 行为

- 关闭：保留原有「全部／视频」入口与动态展示。
- 开启：顶部原生分段 Picker 显示「全部／投稿／番剧／专栏／UP」，宽度随页面调整，左右各留 20pt，沿用现有随滚动隐藏的机制。
- 最常访问区域共用「全部」的数据，不受分类或 UP 筛选影响，头像仍按现有规则进入个人空间或直播间。
- 投稿排除转发、直播和番剧；番剧复用已正式启用的番剧卡片和准确分集播放路径。
- 专栏支持旧 article 和新 opus 元数据，使用现有链接路由打开全文。普通图文不会仅因为使用 opus 结构而在「全部」中变成专栏；专栏分类中的 opus 依赖服务端分类结果。
- UP 通过独立原生弹窗选择，包含最常访问、当前动态取流账号和分页获取的关注用户。搜索仅搜索已经加载的用户，可继续加载关注列表。
- 各分类保存独立列表、游标和滚动位置；UP 按 MID 隔离，保留最近三个用户的列表。账号或实验开关变化时重建模型，清除旧账号状态。

## 请求与分页

沿用 `/x/polymer/web-dynamic/v1/feed/all`：全部/投稿/番剧/专栏分别发送 `type=all/video/pgc/article`。UP 发送 `host_mid`，不发送 `type`，使用动态取流账号认证。关注列表使用 `/x/relation/followings`，每页 50 个，同样使用动态取流账号。

实验开启时，每次加载最多处理三页。屏蔽过滤、空数据或重复内容导致当前页没有新可见内容时，在此上限内续页；达到上限可点击「加载更多」。重复、空游标或服务端结束标志停止续页。跨页去重，并原子提交整批列表和游标：中途失败保留原数据与重试起点。取消、账号变更或模型失效后不提交旧结果。

## 后续验收

1. 实验关闭/开启反复切换，检查顶部布局、最常访问与列表状态。
2. 五个分类逐一加载、下拉刷新及加载更多；番剧跳转准确分集，专栏全文和评论/分享正确。
3. 不同 UP 来回切换，检查列表与滚动位置；切换第四个 UP 后旧缓存可重新加载。
4. 动态取流账号与主账号不同、账号切换、退出登录；确认列表及关注用户不串账号。
5. 开启关键词/广告/带货屏蔽，检查空页不会无限请求；断网后的加载更多与刷新可以重试。
6. 小屏、动态字号、深浅色、降低动态效果；检查五项 Picker 和 UP 弹窗。

当前限制：服务端分类不一定与官方客户端所有推荐/过滤规则一致；UP 搜索是已加载关注用户的本地搜索；列表与滚动位置是当前会话内状态，不跨冷启动持久化。

## 分类切换修正（2026-10-12）

- 移除以模型身份重建整个滚动页的 `.id`；分类之间复用滚动容器和系统边缘效果宿主，按模型身份保存/恢复位置。旧模型迟到的几何回调不会写入新分类。
- 实验顶部使用系统 UISegmentedControl，保持控件身份，并仅在选中项确实不一致时同步索引，避免数据发布重复设置索引打断触摸选中动画。
- 分类数据激活放到选中项对应的可取消任务中，先提交控件选中状态，再更新列表；无固定延迟。快速点击时取消旧激活任务。
- 新增滚动容器复用测试，覆盖不同分类/UP、旧几何回调和回到顶部。测试执行、切换掉帧与动画的真机效果仍需验证，不声明已获得帧率改善数据。
- 应用及测试目标 build-for-testing 成功；指定模拟器未启动，未执行 XCTest。真机 Debug 构建、安装及启动成功（RCe2027，iOS 27.2）；安装成功不代表切换动画和流畅度已完成界面验收。
