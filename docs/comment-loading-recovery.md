# 评论加载完整性与恢复

已转正，视频及动态评论默认使用完整分页与恢复逻辑。开发者诊断中的实验开关、实验偏好读取和旧加载分支均已移除；旧安装保存的关闭偏好不再影响加载。商品评论过滤设置仍独立保留，账号与界面不变。

## 已实施

- 视频和动态根评论优先使用 `next_offset`（包括 `pagination_reply.next_offset`），而非数字 `next`。无 offset 时保留兼容回退。
- 分页错误与取消不再把评论标记为结束，保留已有内容和重试入口。
- 重复页、过滤后的空页最多自动跳过两页。预算用完或游标不前进时暂停自动加载，由现有重试按钮继续；只有服务端结束标记或缺少分页信息的空响应才结束。
- 重试使用最后成功的游标，单页内及跨页按回复 ID 去重。
- 视频过滤订阅使用发布的新值，避免 `@Published` 的 willSet 时序读取旧值；关闭过滤后重新请求，包括原列表已被全部过滤为空的情况。
- 重置楼中楼和对话缓存时使旧请求失效；已打开的弹窗通过内容 revision 重新加载，保留原有深链定位标识。
- 视频本地对话补入已加载的父回复或对话根回复。
- 复用现有列表、弹窗、骨架和重试控件，没有调整评论布局、计数显示或账号路由。

## 依据及边界

此前匿名请求 `oid=170001,type=1,mode=3`：第一页返回 20 条，`next=2` 与 `pagination_reply.next_offset=CAEiAggC` 同时存在。以 `2` 作为 `pagination_str.offset` 请求，返回的 20 条均与第一页重复；以真实 offset 请求，重叠为 0。原去重和结束判断共同使列表提前停止。这是分页问题的直接样本，不代表所有视频都出现同一种差异。

本阶段没有切换评论 API、认证账号或排序规则，也不承诺与官方客户端列表完全一致。服务端账号可见性、审核/折叠与客户端接口差异仍可能影响内容。

**对话分页尚未实施**：`/x/v2/reply/dialog/cursor` 的楼层游标不能复用根评论 offset。[接口资料](https://github.com/pskdje/bilibili-API-collect/blob/main/docs/comment/list.md) 展示了 `min_floor/max_floor`，但本次没有用可重复的实际多页响应验证续页规则。现有对话仍单次请求最多 20 条，后续应独立验证后再加分页与重试。

## 真机验收建议

使用同一账号、视频/动态和排序，关闭商品评论过滤，连续翻页及展开楼中楼。包含断网再恢复、全部内容被过滤后关闭过滤、弹窗内切换过滤、通知深链进入回复。对话超过 20 条的情况仍按上述边界判断。
